# 台职院竞赛小车操作说明（RDK S100 / TROS 原版环境）

> 适用：D_Robot 竞赛方案（lidar_location 定位 + 四阶段静态+动态追点）
> 环境：RDK S100（aarch64）、真 TROS 2.0（/opt/tros/humble）、N10P 雷达、USB 相机、底盘串口 /dev/ttyACM0

---

## 一、快速启动（三脚本）

所有脚本位于 `/root/D_Robot/test/dev_ws/`，按顺序在两个终端分别运行：

### 终端一：总系统（雷达/底盘/定位/感知/相机/TTS/Foxglove）

```bash
cd /root/D_Robot/test/dev_ws && ./start_lidar_location.sh
```

### 终端二：四阶段静态+动态追点（追点/避障主控）

```bash
cd /root/D_Robot/test/dev_ws && ./start_path_follower.sh
```

### 清理全部进程

```bash
cd /root/D_Robot/test/dev_ws && ./stop_all.sh
```

> 启动前若已有进程在跑，先执行 `./stop_all.sh` 再启动。

## 二、追点启动脚本命令行参数（重要）

`start_path_follower.sh` 支持在启动时临时覆盖关键配置（**不修改 yaml 原文件**，退出自动清理临时文件）：

```bash
./start_path_follower.sh [--variant default|backup_45deg] [--static on|off] [--lidar on|off]
```

| 参数 | 作用 | 示例 |
|---|---|---|
| `--variant` | 选择 Task1 路线：`default`（原路线）或 `backup_45deg`（45°起步备用路线） | `--variant backup_45deg` |
| `--static` | 静态避障开关：静态绿色快照 + waypoint_shift 路径偏移 | `--static off` |
| `--lidar` | 实时雷达避障开关：扇形/走廊动态避障（降速转向） | `--lidar off` |

**常用组合：**

```bash
# 仅实时雷达避障（关闭静态避障，分项测试用）
./start_path_follower.sh --static off

# 备用45°路线 + 仅实时雷达避障
./start_path_follower.sh --variant backup_45deg --static off

# 纯航点追线（无任何避障）
./start_path_follower.sh --lidar off --static off

# 查看用法
./start_path_follower.sh --help
```

- 不传的参数沿用 yaml 当前配置
- 参数输入校验：`--variant` 仅接受 `default|backup_45deg`，开关仅接受 `on|off`（自动转成 yaml 布尔值）

## 四、Foxglove 可视化

- 总系统启动后自动开启 `foxglove_bridge`（端口 **8765**），局域网内浏览器打开 `http://<小车IP>:8765`
- 常用话题：
  - `/tf`、`/tf_static`：TF 树（map→odom→base_link→laser/imu_link）
  - `/amcl_pose`、`/lidar_location/match_score`：定位位姿与匹配分数（正常 ≥0.5）
  - `/scan`：雷达点云
  - `/camera/image`、`/camera/qr_roi/image`：相机画面与二维码 ROI
  - `/visual_lidar_path_follower/debug_*`：航点、偏移路线、障碍点
  - `/visual_lidar_path_follower/route_snapshot`：四阶段路线图事件

## 六、日常检查与常见问题

### 启动后确认系统正常

```bash
# 节点数应约 25 个（含两套系统）
ros2 node list | wc -l

# 定位匹配分数（应 ≥0.5）
ros2 topic echo /lidar_location/match_score --once

# 雷达频率（12Hz）
ros2 topic hz /scan
```

### 常见问题

| 现象 | 处理 |
|---|---|
| Foxglove 报缺少 `map → base_link` 变换 | 定位节点偶发 FastDDS 启动死锁：单独重启 `lidar_location` 节点，或 `./stop_all.sh` 后重新启动 |
| 定位晃动 | ① 看 `/amcl_pose` 静止波动（>5cm 需处理）；② 检查 `/lidar_location/match_score`；③ 检查雷达频率是否稳定 12Hz |
| 回 P 点急停倒车退太多 | 调小 `return_brake_reverse_cycles`（当前 10 周期≈0.2s） |
| hobot_tts 反复重启（语音不响） | 检查 USB 扬声器是否插入（`cat /proc/asound/cards` 应有播放设备）；TTS 模型位于 `/opt/tros/humble/lib/hobot_tts/tts_model/` |
| 节点数偏少 | 可能 FastDDS discovery 不完整：确认环境变量 `FASTDDS_BUILTIN_TRANSPORTS=UDPv4` 已设置（脚本已自动处理） |

### 日志查看

```bash
# 启动脚本输出（前台运行直接可见）；后台/自动运行时：
tail -f /tmp/verify_t1.log   # 总系统
tail -f /tmp/verify_t2.log   # 追点

# ROS 官方日志（按时间目录）
ls -t /root/.ros/log/ | head
```

## 七、运行顺序提醒

1. 必须在**打开物理底盘开关前**启动终端二（追点），使绿色静态候选先形成 READY 快照
2. 两套系统只能选一套定位（lidar_location），不要同时跑 AMCL
3. Task1 当前控制点 `(0,0) → (0.60,0.60) → (3.30,0.65) → (4.10,3.60)`，修改 `generate_task1_waypoints.py` 后可重新生成
